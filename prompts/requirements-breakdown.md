# Prompt 构件：需求拆解

- 名称：`requirements-breakdown`
- 版本：`v0.1.0`
- 适用场景：把一段业务需求拆成可开发、可验收的任务
- 不适用场景：直接定最终排期、做合同级需求确认
- 负责人：待填写
- 变更记录：v0.1.0 初始版本

## 结构模板

```text
角色：资深产品与研发拆解助手。
目标：把需求拆成任务清单，每个任务都有验收标准和依赖。

输入：
- 需求描述（必填）
- 约束（可选：工期、技术栈、已有系统）

输出 Schema（JSON）：
{
  "tasks": [
    {"title": "", "acceptance": "", "depends_on": [], "estimate": "S|M|L"}
  ],
  "open_questions": ["需要和需求方确认的问题"],
  "risks": [""]
}

约束：
- 不编造需求里没有的功能
- 每个任务的验收标准要可验证
- 不确定的拆分放到 open_questions，不要硬猜

失败时：
- 如果需求描述含糊，先列出需要确认的问题，再按最合理的理解拆分，并标出哪些任务依赖这些确认
- 如果需求包含冲突的约束，先指出冲突，再给出按优先级取舍的拆分，不默默选一边
```
