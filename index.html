PDE 学习站

Prompt-Driven Engineering：把 Prompt 当软件构件来做，而不是当聊天咒语来写。

核心目标：每个 Prompt（或一组 Prompt）都要结构清楚、行为稳定、能测、能改、能复用。

和相邻概念的分工

  • Prompt Engineering：这一次怎么写才答得好
  • PDD：开发循环快不快（意图 → 生成 → 评估 → 迭代）
  • PDE：这个 Prompt 本身质量够不够
  • POG：全公司怎么管、复用、审计这些资产

学习路线

  1. 概念：Prompt 的生命周期——像代码一样版本、评审、测试、发布
  2. 结构模板：角色 / 目标 / 上下文 / 约束 / 输入输出 Schema / 示例 / 失败处理
  3. 质量清单：见下方自评
  4. 评估：测试用例集、黄金答案、评分标准、回归测试
  5. PDD 迭代：意图 → 生成 → 评估 → 迭代，记录每次改动的原因和效果
  6. POG 治理：目录命名、版本管理、复用、审计、权限和变更记录
