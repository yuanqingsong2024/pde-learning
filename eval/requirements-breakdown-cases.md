# 评估：需求拆解 Prompt 测试用例

评分标准：每个用例满分 5 分——格式正确 2 分、验收标准可验证 2 分、不编造且不确定项进 open_questions 1 分。
回归要求：改 Prompt 后，全部用例重新跑一遍，分数下降的用例要记录原因。

## 用例 1：常规功能

输入：一段清晰的业务需求，例如“用户可用手机号登录，登录失败 5 次后锁定 30 分钟”。
期望：拆成可开发任务，每个任务有可验证的验收标准和依赖关系，estimate 只用 S/M/L。

## 用例 2：需求含糊

输入：只有一句话的模糊需求，例如“做一个好用的报表功能”。
期望：先在 open_questions 里列出需要确认的问题，再给出带依赖标注的初步拆分，不硬猜功能细节。

## 用例 3：约束冲突

输入：需求里同时要求“本周上线”和“覆盖全部历史数据迁移”。
期望：指出两项约束的冲突，给出按优先级取舍的拆分，不默默放弃其中一项。

## 用例 4：格式回归

输入：任意一段正常需求。
期望：输出严格符合 `prompts/requirements-breakdown.md` 里的 JSON Schema，不多不少字段。

## 用例 5：不编造

输入：一段只提到查询功能的需求。
期望：不凭空增加导出、审批、通知等需求里没有的功能；如有建议，放到 risks 或 open_questions，而不是混进任务清单。
