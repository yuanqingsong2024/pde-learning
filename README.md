# PDE 学习站：从全栈开发到 PDE 解决方案工程师

> PDE（Prompt-Driven Engineering）是把 Prompt 当软件构件来做，而不是当聊天咒语来写。
>
> 核心目标：每个 Prompt（或一组 Prompt）都要**结构清楚、行为稳定、能测、能改、能复用**。
>
> 术语提醒：检索未发现 PDE / POG 的统一官方标准定义，本站按工作定义使用；对外沟通时先亮明定义。

**在线访问：** https://yuanqingsong2024.github.io/pde-learning/ （GitHub Pages，分支 main，根目录）

本仓库面向 Java / Web / 小程序背景的全栈开发工程师，目标是 PDE 解决方案工程师：为企业设计、交付并治理提示驱动的 AI 解决方案。

## 和相邻概念的分工

- **Prompt Engineering**：这一次怎么写才答得好
- **PDD**：开发循环快不快（意图 → 生成 → 评估 → 迭代）
- **PDE**：这个 Prompt 本身质量够不够，业务目标如何变成可靠系统
- **POG**：全公司怎么管、复用、审计这些资产

## 学习路线（建议）

- 全职约 3–4 个月、业余约 6 个月走完 0–6 阶段并做出 2 个可展示项目；7–8 阶段在真实项目中持续打磨。
- 最优先的三件事：带结构化输出 + 黄金评测集的 RAG 问答；带工具调用 + 人工确认的审批型工作流；提示入库、版本化并接可观测。
